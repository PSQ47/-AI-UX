# game-ux-wireframe（低保真草图 · 4a）

## When to Use

流程第 **4a** 步，在高保真组装（game-ux-designer）**之前**。
输入 `交互分析.md`，输出**纯文字/ASCII 布局草图**，供人工核对方案。

核心价值：**方案定稿前不碰 Figma、不建 token、不精修**——用最少 token 把"布局 + 控件位置 + 状态"讲清楚，让用户便宜地迭代。

**不要**：画 Figma、建变量、精修样式。那是 4b（game-ux-designer）确认后才做的事。

## Inputs / Outputs

| | |
|---|---|
| 输入 | `交互分析.md` |
| 输出 | `草图_<模块>.md`（ASCII 布局 + 控件清单 + 状态 + 待确认） |
| 依赖 | 无（不连 Figma） |

## Workflow

### 1. 每屏一张 ASCII 布局
用等宽字符画出屏幕框架、区块划分、控件位置。只表达**结构与层级**，不表达视觉。

示例：
```
┌─ P1 货物总览页 ──────────────────────────┐
│ [标题:货物·价格预览]           [月卡专享] │
├──────────────┬───────────────────────────┤
│ 货物类型      │  [卡]  [卡]  [卡]  [卡]    │
│ ▸★星标(选中) │  [卡]  [卡]                │
│  香料        │   卡=icon+星级+名+价       │
│  茶叶        │                            │
│  瓷器        │                            │
└──────────────┴───────────────────────────┘
```

### 2. 控件清单（标注复用意图）
逐控件列出，**标明预期复用的团队库组件名**（供 4b 直接对应）：

| 控件 | 类型 | 复用/团队库组件 | 状态 |
|------|------|----------------|------|
| 左侧列表 | 竖向列表 | `List/Vertical`(待确认库名) | 默认/空 |
| 货物卡片 | 卡片 | `Card/Goods`(待确认库名) | 默认 |
| 出售锁定 | 定制 | 🔴无库→设计师 | 锁定/模糊 |

### 3. 状态与极端态一句话
每屏列出：默认 / 空 / 锁定 / 极端（超长文本等）如何处理。

### 4. 待确认清单
把需要用户拍板的点集中列出（布局取舍、控件选型、状态方案），编号 Q1/Q2…

## 人工核对门 🔶

产出后**停下**，交用户核对。用户反馈"改哪里/选哪个方案"后，就地改草图再确认。**方案未确认，不得进入 4b。**

## Handoff

方案确认后交给 **game-ux-designer（4b）**：按草图 + 已确认的团队库组件名，用 `library` + `instances` 组装高保真。
