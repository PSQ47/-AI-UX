# 游戏 UX 知识库：建设与使用说明

游戏 UX 知识库用于集中管理设计任务所需的背景、规则、组件和历史决策，让设计师与 AI 在开展新任务前有可追溯的依据。它不是游戏规则的权威来源：使用时仍需核对项目当前版本与负责人确认结果。

本目录只介绍通用结构和使用方法，**不包含具体游戏项目的需求、截图或设计资产**。实际知识库应由项目团队建立，并按授权范围管理。

## 建议分类

1. **产品与世界观**：产品定位、目标玩家、题材、术语和叙事背景。
2. **视觉规范**：色彩、字体、材质、构图和动效风格的依据。
3. **设计系统与组件库**：组件来源、使用方式、状态、变体及交付规范。
4. **页面与导航**：页面层级、入口、返回方式和浮层关系。
5. **玩法与系统规则**：开放条件、核心流程、消耗、奖励和限制。
6. **交互模式与状态**：常用控件、空态、加载、错误、锁定与反馈。
7. **文案与本地化**：术语、按钮、提示、数字、时间与单位格式。
8. **设备与技术约束**：目标平台、设计尺寸、适配和导出要求。
9. **参考页面与资产**：截图、素材、来源、适用范围与授权情况。
10. **项目决策与反馈**：已确认方案、待确认事项、评审反馈及废弃原因。

按项目实际需要增减分类；目录已建立不代表资料已齐全。

## 建立步骤

1. **确定范围**：明确项目、版本、使用对象、负责人及访问权限。
2. **收集资料**：优先收集当前需求、代表性页面、组件库、设计尺寸和主要导航规则。
3. **标注来源**：记录来源、适用版本、获取日期、负责人和确认状态；截图与素材另核对授权。
4. **分清事实与判断**：区分已确认规则、历史记录、设计建议和待验证假设；资料冲突时标明差异并请负责人确认。
5. **建立索引**：记录已有资料、缺失项和入口，链接到实际存在的文件，并定期检查。
6. **持续维护**：版本变化或设计反馈出现时更新对应条目，保留必要的决策来源，避免重复建立冲突规则。

## 使用方式

- **需求分析前**：查产品背景、玩法规则和已有决策，将需求转换为流程、控件与状态。
- **设计前**：查页面导航、视觉依据和真实组件；缺失的信息标记为待确认，不自行当作事实。
- **交付前**：核对组件状态、图层结构、技术约束与导出要求；同时检查视觉结果和可编辑结构。
- **任务收尾**：记录已确认决策与未完成事项，将可复用反馈更新到合适的规范中。

## 公开边界

项目知识库可能包含内部玩法、设计稿、人员信息和受版权保护的素材。上传公开仓库前，必须逐项确认公开授权、脱敏及素材使用权；不要将密钥、访问令牌或内部链接放入知识库。
