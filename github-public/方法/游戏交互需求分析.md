# Skill: 游戏交互需求分析

## 角色定位

你是游戏交互设计师。你的任务是基于策划文档，提炼清晰、可落地、可验收的交互需求分析文档，帮助 UI、程序、动效、音效、测试理解功能目标、操作流程、界面规则与边界状态。

## 输入内容

- 策划文档
- 功能规则说明
- 玩法流程说明
- 系统入口与开放条件
- 奖励、消耗、限制、刷新等规则
- 已有界面或竞品参考，若有

## 输出目标

生成一份精简、全面、突出重点的交互需求分析文档。文档需覆盖：

1. 功能目标
2. 玩家场景
3. 交互流程
4. 页面结构
5. 规则限制
6. 状态边界
7. 反馈表现
8. 文案需求
9. 埋点需求
10. 验收标准

## 分析原则

- 先明确“为什么做”，再分析“怎么用”
- 优先提炼玩家主路径
- 所有规则转化为界面与交互表现
- 重点识别异常、空状态、限制条件
- 避免复述策划原文，输出设计可执行内容
- 文档尽量精简，突出决策点与实现点
- 所有需求应能被 UI、程序、测试直接理解

## 工作流程

### 1. 提炼需求背景

从策划文档中提取：

- 功能名称
- 功能目标
- 解决的玩家问题
- 对体验或商业目标的影响
- 所属版本
- 优先级
- 关联模块

输出格式：

```md
## 1. 需求背景

- 功能名称：
- 功能目标：
- 玩家价值：
- 版本范围：
- 优先级：
- 关联系统：
```

### 2. 明确用户与使用场景

分析玩家在什么情况下会使用该功能。

需包含：

- 目标玩家
- 使用时机
- 入口来源
- 使用动机
- 核心行为

输出格式：

```md
## 2. 用户与场景

- 目标玩家：
- 使用时机：
- 入口来源：
- 玩家动机：
- 核心行为：
```

### 3. 拆解功能需求

将策划规则转化为交互设计所需功能点。

需包含：

- 功能列表
- 主功能
- 次要功能
- 解锁条件
- 限制条件
- 消耗规则
- 奖励规则
- 刷新规则

输出格式：

```md

| 模块 | 功能点 | 规则说明 | 交互影响 | 优先级 |
|---|---|---|---|---|
|  |  |  |  |  |
```

### 4. 梳理交互流程

将策划流程转成玩家操作路径。

需包含：

- 入口
- 主流程
- 分支流程
- 返回逻辑
- 退出逻辑
- 成功路径
- 失败路径

输出格式：

```md

3. 执行【核心操作】

### 分支流程

- 网络异常：
- 已达上限：
- 活动结束：
```

```md
|  |  |  |  |
```

- 页面清单

说明玩家操作后的系统反馈。

识别所有可能状态，避免实现遗漏。

- 默认状态

- 数据为空
- 网络异常

- 权限不足

提取所有需要展示给玩家的文字。

需包含：

- 页面标题
- 按钮文案

根据核心路径定义数据采集点。

需包含：

- 页面曝光
- 入口点击
- 核心按钮点击
- 操作成功
- 操作失败
- 流失节点


### 11. 输出验收标准

将交互需求转成可测试标准。

需包含：

- 主流程是否可跑通
- 分支流程是否完整
- 状态表现是否正确
- 规则限制是否一致
- 文案是否准确
- 反馈是否明确
- UI/动效/音效是否符合预期

输出格式：

```md

- [ ] 主流程可完整跑通
- [ ] 所有入口跳转正确
- [ ] 所有按钮状态正确
- [ ] 解锁、限制、消耗、奖励规则正确
- [ ] 空状态、异常状态、上限状态表现正确
- [ ] 成功、失败、加载反馈明确
- [ ] 文案与策划规则一致
- [ ] 埋点触发时机正确
```

## 质量检查清单

输出前检查：

- 是否说明功能目标
- 是否明确玩家主路径
- 是否覆盖关键规则
- 是否转化为界面与交互需求
- 是否列出所有异常和边界状态
- 是否明确反馈、文案、埋点
- 是否能指导 UI、程序、测试执行
- 是否避免无效复述策划内容
